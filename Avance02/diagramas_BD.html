Leyenda de relaciones (cardinalidad):

  • USUARIO 1 — 1 SOCIO (cada socio es un usuario con rol SOCIO)
  • SOCIO 1 — N MEMBRESÍA (un socio puede tener varias membresías a lo largo del tiempo)
  • PLAN 1 — N MEMBRESÍA (un plan se contrata en muchas membresías)
  • MEMBRESÍA 1 — N PAGO (una membresía puede generar varios pagos: inicial, renovación)
  • SEDE 1 — N CLASE (una sede ofrece varias clases)
  • CLASE 1 — N HORARIO_CLASE (una clase tiene horarios específicos con cupos)
  • CLASE 1 — N RESERVA (una clase puede tener muchas reservas)
  • SOCIO 1 — N RESERVA (un socio hace múltiples reservas)
  • SOCIO 1 — N ASISTENCIA (un socio acumula múltiples asistencias)
  • SEDE 1 — N ASISTENCIA (una sede recibe múltiples registros)

Restricciones del modelo físico (MySQL):

  • Motor: InnoDB (soporte transaccional + integridad referencial)
  • Charset: utf8mb4 con collation utf8mb4_unicode_ci
  • Todas las PK son INT AUTO_INCREMENT
  • FKs definidas con FOREIGN KEY ... REFERENCES
  • Campos únicos: USUARIO.correo, SOCIO.dni, SOCIO.id_usuario
  • Tipos ENUM definidos:
    • USUARIO.rol: 'SOCIO','ADMIN'
    • PLAN_MEMBRESIA.tipo: 'BASIC','PREM','ANUAL'
    • MEMBRESIA.estado: 'ACT','VEN','SUS'
    • PAGO.metodo: 'YAPE','PLIN','TARJ'
    • PAGO.estado: 'OK','FAIL','REF'
    • CLASE.tipo: 'CROSS','YOGA','SPIN','ZUMBA','FUNC','BOX','PILATES'
    • HORARIO_CLASE.estado: 'DISP','LLENO'
    • RESERVA.estado: 'CONF','CAN','LE'
    • ASISTENCIA.tipo: 'ING','SAL'
  • Índices: idx_memb_estado, idx_memb_fechafin, idx_pago_fecha, idx_asis_fecha
  • Restricciones únicas compuestas: uk_horario_fecha (id_clase, fecha_especifica), uk_res_socio_clase_fecha
